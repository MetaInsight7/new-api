# Static 官网模型报价与排行榜接口适配

状态：用户已确认 Spec 与测试边界；三个本地 Tickets 已完成、验证并独立提交。实际结果见 [验收记录](verification.md)。尚未推送或部署。

## Problem Statement

独立 Static 官网应继续使用现有设计语言，并正确展示迁移到 `tokendazi_op` 后的模型报价与排行榜。当前模型页沿用旧的倍率与按次判断，缺少模型专属倍率，并把表达式定价笼统显示成“动态计费”。部分金额提前舍入后失真，缓存、阶梯、分时和任务计费来源也未完整呈现。

公开定价接口已有模型、供应商、可见分组及大部分计费元信息，但缺少官网计算模型专属分组报价所需的数据。排行榜页面还存在与现有 API 不兼容的周期选项，需要适配现有接口而不是扩张后端排行榜功能。

目标不是照搬旧 Overlay 覆盖更丰富的 Base 计费能力，也不是重做整个官网或 Console，而是在保留现有视觉和产品行为的前提下补齐这两个公开页面的契约适配。

## Solution

官网模型页继续使用匿名公开报价，保留分组选择、“全部 · 最优”、桌面价目表与移动卡片。后端在原生公开定价接口中最小补充模型专属倍率，前端按可见分组的有效倍率计算实际展示报价。

Token 主摘要显示首档输入、输出参考价，缓存及完整阶梯放在展开详情。分时基价沿用真正 Base `main` 的展示政策，可靠可识别时显示当前时段首档价并自动更新，所有时段规则仍可展开。分时附加倍率独立列出，不混入基础单价。非 Token 计费按真实单位显示，多个来源分别展示，不能安全解释的报价明确说明原因。

排行榜前端适配已有的四个 API 周期及返回结构，保留现有周期文案、前端 ×100 展示倍率和近 30 日模拟曲线，不新增公开模拟标注，不把展示算法写入后端真实统计。

## User Stories

1. 作为官网访客，我希望模型页延续现有 Static 风格，以便无需适应一套新的页面布局。
2. 作为桌面访客，我希望继续使用价目表查看模型，以便快速比较输入和输出参考价。
3. 作为移动访客，我希望卡片与桌面使用相同的报价口径，以便在不同设备上看到一致的结果。
4. 作为未登录访客，我希望查看公开分组下的模型报价，以便了解服务价格而不需要先注册。
5. 作为访客，我希望只能选择公开可见且该模型可用的分组，以便不会看到实际不可选的报价。
6. 作为访客，我希望选定分组后使用模型的有效专属倍率，以便看到与该分组定价规则一致的参考价。
7. 作为访客，我希望“全部 · 最优”按该模型在可见分组中的生效倍率选组，以便不会因忽略专属倍率而选错报价。
8. 作为访客，我希望免费配置与缺少配置有不同的表现，以便不会把无法报价误认为免费使用。
9. 作为访客，我希望 Token 主摘要保持首档输入、输出两项，以便页面仍然紧凑且易于比较。
10. 作为访客，我希望知道首档价格的适用条件，以便不会把首档参考价误认为所有阶梯的最低价。
11. 作为访客，我希望展开查看完整阶梯，以便了解上下文长度等条件变化后的价格。
12. 作为访客，我希望展开查看缓存读取、缓存创建 5m/1h、图片及音频等单列价格，以便了解输入输出摘要之外的计费项目。
13. 作为访客，我希望分时基价显示当前时段的首档参考价，以便无需自己先判断当前时段。
14. 作为访客，我希望时段切换或重新回到页面时自动更新参考价，以便页面不会长期停留在旧时段。
15. 作为访客，我希望展开查看所有时段、时区及阶梯规则，以便理解分时价格的适用范围。
16. 作为访客，我希望时间或请求条件触发的附加倍率单独呈现，以便不会把基础价当成包含全部附加规则的最终费用。
17. 作为访客，我希望按次、按张、按秒、Token 和 credit 计费使用各自单位，以便正确比较同类价格。
18. 作为访客，我希望不同插件或 provider 的计费来源分别展示，以便不会看到无法实际执行的拼合最低价。
19. 作为访客，我希望无法可靠解释的表达式或未配置来源显示明确原因，以便不会被零价或旧价误导。
20. 作为访客，我希望小额非零价格保留有意义的精度，以便价格不会因为显示舍入而变成免费。
21. 作为访客，我希望在线数据和匿名快照使用一致的解释口径，以便切换数据来源时不会无故改变计费含义。
22. 作为访客，我希望搜索、供应商、分组、计费筛选和分页继续工作，以便价格适配不会破坏原有浏览方式。
23. 作为排行榜访客，我希望四个现有周期能正常切换，以便不会因不支持的 API 参数而遇到错误。
24. 作为官网运营者，我希望排行榜保留现有周期文案、展示倍率和趋势算法，以便接口适配不会顺便改动既有展示政策。
25. 作为排行榜访客，我希望失败刷新不会把旧数据误配到另一个已选周期，以便页面状态与实际展示数据一致。
26. 作为维护者，我希望官网报价复用 Base 的表达式解析能力，以便后续官方更新时不需要维护另一套不一致的解析器或结算引擎。
27. 作为维护者，我希望每个功能独立验证并提交，以便后续维护和回滚能够定位到实际功能。

## Implementation Decisions

### 范围与数据边界

- 实现目标是 `new-api/tokendazi_op` 与独立 Static 官网。真正 Base `main` 用于核对原生能力，Overlay 最终分支用于核对既有产品行为，不能把迁移分支误认成官方实现。
- 本轮只涵盖公开模型报价所需的后端增量，以及 Static 模型页和排行榜页的适配。既有首页、导航和部署审计建议不自动扩张成本轮任务。
- 延续官网匿名公开取数和匿名快照机制，不引入用户专属报价，不扩大公开分组，不修改认证或数据库结构。
- 不修改预扣、结算、退款、用量归一化、真实用量报表或排行榜后端聚合。

### 原生公开定价接口的最小补充

- 继续使用 `/api/pricing`，不另建官网聚合接口或完整后端报价计算引擎。
- 增加兼容字段 `group_model_ratio`，表达“公开可见分组 → 响应中已公开的模型名称 → 已配置的专属覆盖倍率”。没有专属配置的项目不伪装成已配置，显式零保留。
- 模型匹配在服务端复用现有专属倍率解析规则，输出与该响应模型名称一致的键；Static 不另写一套模型名称归一化或通配符匹配。
- 新字段只包含该响应允许展示的分组、模型及其适用关系，不直接导出完整管理员配置映射或隐藏的模型名。
- 保持原有字段、模型元信息、分组权限及已登录调用者的既有行为。原消费者可忽略新字段，新消费者在旧响应没有该字段时只能沿用已有分组倍率，不能推测不存在的专属配置。

### 分组、金额与精度

- 模型展示价采用有效倍率：已配置模型专属倍率优先，否则使用接口给出的适用分组倍率。倍率只折算一次，不将专属倍率与默认分组倍率连乘。
- 模型可用分组按公开 `usable_group` 与模型启用关系裁剪、去重；模型启用关系中的 `all` 仅展开为该响应的可见分组，不成为独立报价分组。
- “全部 · 最优”比较同一模型、同一计费条件下可见分组的折算价，不跨阶梯、时段或不同 provider 拼合价格。
- 分组选择器显示的默认分组倍率与模型的有效倍率要区分，模型行的专属配置不能继续显示成该分组通用倍率。
- 传统 Token 模式保留原有基础倍率换算语义，表达式的 Token 系数直接采用美元/百万 Token，固定价格采用其实际单位，不额外应用传统倍率换算。
- 只在最终显示阶段格式化金额，避免中间 `toFixed` 丢失精度。非零小额必须保持有意义的显示精度，非法数值和缺失项目不当成零；明确配置的零价正常展示。

### 表达式解释与前端复用

- 复用当前 Base 的纯表达式编译、结构化读取和时间条件解释能力，配以窄的官网展示适配层；不另造正则表达式计费解析器，不使用动态 `eval`。
- 官网仍是独立 Static，不引入 React、Console store、管理接口或货币设置组件作为运行时依赖。
- 纯解析能力以可复现、带源版本记录的浏览器产物提供给官网，保留原有许可证和归属信息；新代码不增加许可证头。产物可独立更新，不复制整套 Console 组件。
- 在线显示、匿名快照及其验证共用同一报价解释口径，保留表达式版本与计费来源元信息，不把最终格式化字符串作为后续计算输入。

### 首档、明细与其他计费模式

- 桌面主表和移动卡片保留首档输入、输出两项 Token 摘要，提供简短阶梯标记和适用条件，完整阶梯放在展开区。
- 缓存读取、缓存创建 5m/1h、图片、图片缓存和音频等单列项目属于同一档的明细，不跨档混用；未单列项目不伪装为免费。
- 单分组模型也能展开计费详情，入口不能仅依赖原有多分组按钮。多分组报价与计费明细共用现有展开空间，延续 Static 设计语言。
- 按次、按张、按秒和 credit 等项目按真实单位呈现，不强塞成 Token 输入输出价；混合模式分别显示单位及条件，附加常数不并入单位价格。
- 读取接口提供的插件/provider 变体及 schema，不仅依据顶层 `quota_type`、`billing_mode` 或旧倍率判断价格。
- 多来源明细分别展示；只有单位和条件确实可比时可使用范围摘要，不向用户承诺能选择实际不存在的最便宜 provider 路由。
- 无法完整解释的特殊表达式、未知版本、缺少 schema 或未配置来源显示明确状态，不提取局部系数冒充完整价格，也不回退旧倍率。详情中的公开原文作为文本安全转义，不作为 HTML 或脚本执行。

### 分时展示

- 沿用真正 Base `main` 的分层政策：可靠可识别的 Token 分时基价先选当前时段，再展示该时段第一阶梯，并提供“当前时段价格 / 分时计费”提示。
- 展开区保留所有时段、时区、条件及阶梯，摘要选择当前档不会删除其他规则。
- 时间条件或请求条件触发的附加倍率独立列出，基础价格摘要不把这些倍率静默乘入单价。
- 当前时段使用表达式声明的时区和当前时间，不根据用户浏览器所在地猜服务器时区；无法可靠确定服务器 `Local` 或其他适用条件时，只展示规则与原因，不猜数字。
- 复用 Base 的分钟边界和页面可见性刷新语义，采用共享时钟，非分时模型不持续订阅。刷新本地展示而非每分钟重新取完整 API。
- 快照保存原始规则及报价元信息，浏览器使用当前时间解释；不得将快照生成时刻的“当前价”永久冻结为在线当前价。
- 任务计费、特殊表达式和附加倍率不强行套用 Token 分时基价选择器，继续遵循各自结构化单位和可靠降级政策。

### 排行榜适配

- 使用现有 `/api/rankings`，仅发送 `today/week/month/year`，不修改后端周期支持，不请求 `all`。
- 保留“今天 / 本周 / 本月 / 本年”等既有文案，不新增模拟数据标注。前端不再提供会发出不支持参数的“全部”操作。
- 按现有返回的模型榜单及历史模型汇总字段适配数据，包括模型名称、供应商、排名、Token 量和占比。安全处理空数组、零总量及加载错误。
- 前端 Token 展示乘 100 一次；每次渲染从原始响应推导，不污染原始缓存，不因重复刷新或切换周期再次放大。统一放大不改变排名和占比。
- 保留既有近 30 日模拟曲线算法政策，以所选周期返回的模型汇总作为输入，不改用真实历史 points 绘图。
- 最新成功数据与其周期绑定，过期响应不能覆盖后发请求；刷新失败保留上次成功结果时，周期选中状态与这份结果保持一致。
- 不重做排行榜布局、主题、文案或增加供应商榜等新板块。

## Testing Decisions

### 测试边界

- 首选两条外部可观察边界：公开报价 HTTP 响应，以及 Static 页面实际渲染和交互。它们覆盖后端与独立官网之间的契约，不以私有函数调用次数或模块结构为断言。
- 后端复用已有分组倍率测试的配置案例，增加公开接口响应回归；不为小增量散落大量低层测试文件。
- Static 沿用已有 Node 测试和快照验证模式，对同一输入断言最终报价、单位、可见分组和安全降级；不是仅断言字符串拼接或代码内部实现。
- 页面改动必须用 Playwright 验收，使用真实当前 API 与确定性公开响应 fixture 两种场景。默认不调用收费上游、不压测、不依赖真实账号写入来构造价格案例。

### 关键案例

- 普通分组倍率、模型专属覆盖、显式零、未配置覆盖，以及归一化模型名称的现有匹配行为。
- 隐藏组、模型不属于某组、空分组、重复分组及 `all` 展开；输出不包含隐藏配置，组选择和最优选择一致。
- 标准传统 Token 价、固定按次价、表达式 Token 首档、多阶梯、只有某项价格、缓存 5m/1h、图片及音频明细。
- 同一模型不同计费来源、单一来源保留 override、未配置来源、不同 schema 单位、混合价格和附加常数。
- 非零小额、显式免费、缺少值、非法值、未知表达式版本及不能完整解释的语法；不得显示伪造零价或局部报价。
- 分时边界前后、页面隐藏再显示、显式时区、服务器 `Local` 无法确定，以及时间条件附加倍率与分时基价的区别。用固定时间测试，不等待真实分钟边界。
- 在线响应与同一数据生成的匿名快照一致，快照不冻结当前时段，错误响应不替换有效快照；无登录凭据的快照生成保持原边界。
- 四个排行周期均成功适配，页面不请求 `all`；重复切换不造成 ×100 重复放大，占比和排名不变，模拟曲线保持既有政策。
- 排行空数据、刷新失败、异步响应乱序及周期状态一致性；不需要调用真实上游增加 Token 量。
- 桌面和移动视口的摘要、展开、分组切换、过滤与分页；无新增控制台错误、横向溢出或表达式/模型原文引起的脚本执行。

### 验证与报告

- 针对受影响模块运行完整测试、静态检查和必要构建，而非默认重跑整个 Console 测试集合。
- Bun 构建或测试采用资源受限方式，后端使用正常的针对性测试；不进行压测。
- 修改数据库行为时才触发仓库要求的真实多数据库验证；本方案不修改 schema、查询或驱动，不以本次测试声称完成整个项目的数据库兼容验收。
- 记录实际执行命令、结果和 Playwright 证据。规划文档中的测试列表不能当作已执行结果。

## Out of Scope

- 排行榜后端 `all` 周期、新的统计聚合口径、真实趋势替换、展示 Token 写回后端及文案校正。
- 登录用户专属报价进入官网或公开快照，PLG 分组、官网专用定价 v2、另一套报价缓存。
- 新增或修改模型价格配置、插件宿主/执行契约、预扣与结算规则、数据库结构、认证及账号权限。
- Console 可用模型页重做、管理员模型元数据页面外移、Static 重写为 React、全站主题或布局调整。
- 自动实施首页、全站导航、获客归因、Nginx 和部署审计中的其他候选建议。
- 自动创建 GitHub Coding Plan issue、推送、切换分支或把未完成业务标为完成。
