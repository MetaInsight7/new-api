## 2. 已确认的功能边界

- 重点适配独立官网 `/models`，保留 Static 设计语言、桌面价目表和移动卡片，不重写为 React。
- 后端复用 `/api/pricing`，最小补充模型专属倍率所需公开数据，不另建官网定价聚合 API。
- 保留现有匿名公开取数与快照机制，不引入登录用户专属报价，也不将用户专属数据写入公开快照。
- 延续现有分组折算价和“全部 · 最优”选择，最优仅指模型同一报价条件下、公开可见分组间的最优价格。
- 模型专属倍率是有效倍率的覆盖值，不与分组倍率连乘；显式零与未配置必须区别处理。
- `/models` 适配表达式、阶梯、缓存、分时及当前接口已有的其他计费来源；具体展示政策见第 5 节。
- 用户确认 Q1：保留输入、输出两项首档参考价摘要；阶梯条件、缓存、音频等单列价格及完整阶梯放在展开区。
- 用户确认 Q3：非 Token 计费按实际单位显示，多个来源分别展示；无法可靠报价时说明原因，不报零价或回退旧价。
- 用户确认 Q2：沿用真正 Base `main` 的分层口径，可靠可识别的 Token 分时基价展示当前时段首档价，提示当前时段价格并可展开完整规则；分时附加倍率单列，不混入基础单价；无法可靠判断时不猜价格。
- 独立官网 `/rankings` 同样纳入前端适配，消费 `tokendazi_op` 现有 `/api/rankings` 返回结构。
- 排行榜仅使用现有 `today/week/month/year` 四个周期，不给后端补 `all`，前端不再请求不支持的周期。
- 保留排行榜前端 ×100 展示倍率与近 30 日模拟趋势；真实历史 points 不用于替换已确认的模拟曲线。
- 排行榜倍率不进入后端聚合、数据库、真实用量报表或计费结算。
- 用户确认 Q4：保留现有“今天 / 本周 / 本月 / 本年”等周期文案，不新增公开的模拟数据标注；仅适配 API 与保留的模拟展示逻辑。内部文档继续区分真实统计与展示数据。

## 4. 已核实事实与验收边界

- Overlay Static 在 `web/tokendazi_static/assets/rankings.js:2` 定义 `SCALE = 100`；独立官网 `assets/rankings.js:2` 相同。
- Overlay Console 在 `web/default/src/features/rankings/hooks/use-rankings.ts:26` 定义 `TOKEN_DISPLAY_SCALE = 100`。
- Overlay 后端按 `quota_data.token_used` 聚合并直接返回真实 Token 数，没有对应的展示放大。
- `tokendazi_op/service/rankings.go` 四个周期实际是滚动 24 小时、7 日、30 日、365 日，而非自然日、自然周、自然月或自然年。
- 真正 Base `main` 的 `web/src/features/pricing/lib/dynamic-price.ts:502` 对可识别的 Token 分时基价选择当前时段，对该时段取首个阶梯；任务计费不走此 Token 分时选择分支。
- `main` 的价格单元格与模型卡片显示“当前时段价格”；详情保留所有时段、阶梯及条件，不只保留摘要的当前档。
- `main` 的 `use-billing-time.ts:28` 使用共享分钟时钟，在分钟边界和页面可见性变化时刷新展示；它不是每分钟重新请求报价接口。
- `main` 将请求附加规则从基础表达式分离，详情独立展示条件倍率及时间条件；基础价格摘要不把这些附加倍率直接乘入单价。
- `main` 无法确定服务器 `Local` 时区的当前条件时，不会匹配出有效当前时段；不能把任意含时间表达式一概视为可展示的实时数字报价。
- 当前 Static 主表与移动卡片保留输入、输出两项摘要；非空计费表达式仍显示旧的“动态计费”占位，且没有使用模型专属倍率。
- 正常的传统 Token 基价换算 ×2 与排行榜展示 ×100 是两个无关概念，不可混淆。
- 缺失、非法或无法可靠解释的报价不能冒充免费；显式零价格不能被默认值覆盖。小额非零价格不能因过早舍入而显示成零。
- 实时接口与匿名快照应使用相同的价格解释和格式化口径；快照的生成时间不能冒充当前分时时段。
- 前端实现后进行 Playwright 验收，覆盖桌面、移动、分组切换、计费模式与排行周期切换；构建时遵循资源约束。

## 5. 展示决策与当前设计树前沿

Q1–Q4 均已由用户明确作答，设计树的业务决策前沿已清空，不再重复询问。

### Q1：Token 主表摘要与展开内容（已确认）

用户选择按推荐执行：桌面主表和移动卡片继续展示首档输入、输出参考价，附阶梯标记及适用条件；缓存读取、缓存创建 5m/1h、音频/图片等单列价格和完整阶梯置于现有展开区。首档不称为跨档最低价。

### Q2：分时价格的展示口径（已确认）

用户先询问真正 Base `main` 的展示方式，核对事实见第 4 节；随后明确确认沿用该方案。

已确认沿用 Base 的分层口径：可可靠判断的 Token 分时基价显示当前时段首档参考价，并提示“当前时段价格 / 分时计费”；展开区保留所有时段、时区和完整阶梯。分时附加倍率在详情中独立列出，不冒充基础单价。无法可靠解析或判断时段时只展示规则与原因，不猜数字。采用分钟边界及页面重新可见时更新展示，不用快照生成时刻冻结当前价。

### Q3：非 Token 计费与多个计费来源（已确认）

用户选择按推荐执行：按次、按张、按秒、credit 等计费按真实单位显示，不强塞进 Token 输入/输出价格。多个插件/provider 的详情分别展示，不能拼出不存在的最低账单；只有相同单位且条件可比时才可用范围摘要。无法解释、缺少配置或未知格式时显示明确原因，不显示零价或回退旧价。

### Q4：排行榜周期与模拟趋势的说明（已确认）

用户未采用修改文案的建议：保留现有四个周期文案，不主动新增模拟数据标注。只对齐现有 API 与既有模拟数据展示，保留 ×100 展示倍率和近 30 日模拟曲线；不新增后端 `all`，不请求该不支持的周期。滚动周期与自然周期的实际差异仅作为内部契约事实记录，不主动修改页面文案。
