# 03: 覆盖 Responses WebSocket 有损续接

**What to build:** WebSocket `response.create` 在上游接受前因加密推理状态被拒绝时，在当前渠道透明清理并重发；仍失败后遵守普通渠道重试，而客户端只接收最终结果。

**Blocked by:** 01/打通 HTTP Responses 有损续接.

**Status:** completed (2026-10-12)

- [x] 接受前的精确代码和窄消息拒绝能够触发同渠道额外重发。
- [x] 同一个 `response.create` 最多执行一次清理；新的 `response.create` 拥有独立恢复状态。
- [x] 恢复成功前不锁定错误的渠道亲和，也不把首次拒绝发送给客户端。
- [x] 恢复仍失败时按普通预算选择后续渠道，并沿用已清理请求。
- [x] 已经接受或开始输出的请求不重放，保持单终态。
- [x] 渠道切换时旧连接事件不能污染新尝试，连接、并发槽和计费生命周期正确释放。
- [x] WebSocket 高层集成测试覆盖同渠道成功、换渠成功、最终失败和关闭开关。
