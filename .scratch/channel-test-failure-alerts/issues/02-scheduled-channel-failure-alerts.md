# 02: 打通自动测试失败钉钉告警

**What to build:** 既有自动渠道测试失败后，可收到脱敏的钉钉失败告警；批次、签名、渠道告警冷却和多实例预占组成无需 AI 即可使用的完整闭环。

**Blocked by:** 01 — 统一监控配置，纠正 Codex 独立配置。

**Status:** resolved

- [x] 同一次既有自动测试结果生成告警，包含实际参与测试的 Codex 渠道，不新增上游调用。
- [x] 保留三种测试模式、并发、进度与手动测试通知语义；官方状态通知继续保留，不跨类型合并。
- [x] 5 条失败候选触发批次，正常结束发送尾批；无可发送条目不调用外部服务。
- [x] 规则式脱敏、可选签名及明确投递确认有效，错误诊断不泄露凭据。
- [x] 按渠道持久化冷却和 token 限定预占 / 提交 / 回滚有效；数据库故障可降级本地冷却，明确其局限。
- [x] 尽力投递，不持久化消息或补发；发送失败不改变测试结果和治理判断。
- [x] 租约丢失或取消中止外部 HTTP，不发送未开始批次及尾批，并释放自己的预占。
- [x] 在系统任务主边界回归，并完成真实 SQLite / MySQL / PostgreSQL fresh、upgrade、重复迁移及事务竞争验证。

## Answer

- 已接入既有自动任务结果归并，支持 5 条批次、正常尾批、规则式脱敏、签名、严格确认和按渠道冷却；保留 OP 测试 / 任务行为及两类原有状态通知。
- 取消与租约边界贯通 DNS、AI 和钉钉 HTTP；失败只释放自己的预占，不改变测试结论或自动补发。真实三引擎矩阵、发布版启动升级及 race 均通过，见 [verification.md](../verification.md)；双轴复审见 [review.md](../review.md)。
