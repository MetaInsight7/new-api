# 05: 渠道列表实时并发快照

**What to build:** 拥有渠道读取权限的管理员可在渠道列表当前页的桌面表格与默认卡片中查看受限渠道的实时渠道并发快照；状态查询沿用路由调度的有界负载观察能力，按页面可见性低频刷新并在故障时保留最后成功结果，同时保持无限制渠道、标签汇总行和移动布局的既定语义。

**Blocked by:** 03

**Status:** implemented

- [x] 渠道并发快照状态 API 要求 `ChannelRead`，并声明等价的 PAT scope；未认证、缺少渠道读取权限或 scope 不匹配的请求均被拒绝，授权主体可以只读获取状态。
- [x] 状态 API 一次最多接受 200 个逗号分隔的原始 ID 片段，超过上限返回 HTTP 400；空白、格式错误、零和负数片段被忽略，没有有效 ID 时成功返回空数组。
- [x] 状态 API 只返回数据库中存在且渠道并发上限大于零的渠道，并为每项提供渠道 ID、渠道并发上限、活跃请求数、等待请求数和并发冷却状态；缺失渠道与无限制渠道不产生占位项或额外状态读取。
- [x] 管理侧状态查询与请求路由共享 Ticket 03 建立的同一套有界负载快照缓存、合并读取、分批抓取、并发槽位和超时预算，不建立第二套无界读取路径；任何快照都只用于观察与排序，绝不缓存、授予或推测槽位所有权。
- [x] 列表只从当前页真实渠道行收集渠道并发上限大于零的 ID，并稳定排序、去重；标签模式纳入当前页标签下的真实子渠道但不纳入标签汇总行，集合为空时不发起状态请求。
- [x] 每个查询集合在进入页面后立即获取一次快照，页面可见时此后每 10 秒刷新；页面隐藏时暂停轮询，恢复可见后继续刷新，集合变化或组件卸载后不再沿用旧集合的定时任务或状态映射。
- [x] 首次发生网络错误、非成功 HTTP 状态或业务失败时显示 `-`；已有成功结果后，任一刷新失败都静默保留该集合最后一次成功快照，不清零、不闪烁、不重复提示，后续成功刷新仍可正常替换旧结果。
- [x] 桌面表格与默认桌面卡片显示一致的只读状态：受限渠道展示 `active/max`，等待数大于零时追加 `+N`，处于并发冷却时追加蓝色 `Cooling`；活跃数为零、未满载和达到或超过上限分别使用灰、黄、红状态。
- [x] 桌面表格中的渠道并发状态默认可见、不可排序并继续服从现有列显示偏好；无限制渠道不显示虚构快照，标签汇总行显示 `-`，移动表格与移动卡片均隐藏渠道并发状态。
- [x] `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi` 均提供一致的渠道并发快照、等待和 `Cooling` 文案及无障碍语义，没有缺失键或意外回退。
- [x] 定向 HTTP 测试覆盖认证、`ChannelRead`、PAT scope、200 个原始片段边界、畸形片段、空结果、缺失与无限制渠道过滤、完整返回字段，以及与路由共享有界负载读取预算且不缓存槽位所有权。
- [x] 定向组件测试使用受控响应、假时钟和页面可见性事件，覆盖当前页及标签子渠道去重、立即请求、精确 10 秒轮询、后台暂停与恢复、失败保留、桌面表格与默认卡片状态、无限制与标签汇总语义、移动隐藏和七语静态键完整性。
