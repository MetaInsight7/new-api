# 04: 在运维设置中管理完整渠道并发策略

**What to build:** Root 管理员可在“系统设置 → 运维”的“渠道并发限制”面板查看并管理全部 12 项渠道并发策略；常用策略与高级运行参数始终可见，关联开关只禁用而不丢失下属值，表单采用已确认的默认值与运行边界，只按稳定顺序保存实际变化，并在无变化或顺序保存部分失败时如实反馈。七种受支持语言提供一致的标签、说明、校验和保存体验。

**Blocked by:** 03

**Status:** implemented

- [x] 只有 Root 管理员能够进入和操作“系统设置 → 运维 → 渠道并发限制”面板，面板完整加载当前渠道并发策略值。
- [x] “常用策略”始终显示并发满时等待、等待超时、单渠道最大等待数、启用并发冷却、并发冷却时长、HTTP 429 触发并发冷却、模糊错误消息触发并发冷却和启用负载快照缓存共 8 项。
- [x] “高级运行参数”始终显示槽位 TTL、等待轮询间隔、负载快照缓存 TTL 和每轮最大抢占次数共 4 项，不折叠或隐藏为专家设置。
- [x] 缺失设置采用已确认默认值：等待开启、等待超时 5000ms、单渠道最大等待数 0、并发冷却开启、冷却 30s、HTTP 429 冷却开启、模糊消息冷却关闭、负载快照缓存开启、槽位 TTL 30min、等待轮询间隔 100ms、缓存 TTL 200ms、每轮最大抢占次数 8。
- [x] 数值设置只接受整数并在保存前遵守运行边界：等待超时为 1–60000ms，单渠道最大等待数为 0–10000，冷却时长为 1–3600s，槽位 TTL 为 1–1440min，等待轮询间隔和缓存 TTL 均为 1–5000ms，每轮最大抢占次数为 1–100；非法值有就地反馈且不会发送保存请求。
- [x] 关闭等待后，等待超时、单渠道最大等待数和等待轮询间隔保持可见但禁用并保值；关闭并发冷却后，冷却时长及两个冷却触发开关保持可见但禁用并保值；关闭负载快照缓存后，缓存 TTL 保持可见但禁用并保值。
- [x] 重新开启关联功能后，其下属值恢复可编辑；槽位 TTL 与每轮最大抢占次数始终可编辑，单渠道最大等待数为 0 时明确说明自动跟随渠道并发上限。
- [x] 保存以已加载值为基线，仅按面板定义的固定顺序逐项提交实际变化的设置并等待每项结果；没有变化时不发送请求，并反馈“无更改可保存”。
- [x] 所有变化项保存成功后才显示整体成功；任一项失败时立即停止后续提交，不回滚此前成功项，不宣称整体成功，并明确反馈设置可能已部分生效。
- [x] 部分失败后重新加载会以服务端实际值重建表单基线，尚未保存的项目仍可再次编辑和提交，界面不会把本地预期值冒充为已持久化值。
- [x] `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi` 均覆盖面板标题、分组、12 项标签、帮助说明、依赖禁用状态、边界校验、无更改、成功和部分失败反馈，且没有缺失键或意外回退。
- [x] 定向组件测试覆盖 Root 面板、12 项呈现、默认值与边界、依赖禁用并保值、changed-only 稳定顺序、无变化和中途失败停止；相关 TypeScript 类型检查与 lint 检查通过。
