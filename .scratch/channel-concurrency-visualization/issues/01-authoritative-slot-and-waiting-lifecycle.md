# 01: 权威槽位与等待生命周期

**What to build:** 受渠道并发上限约束的请求在普通选择、指定渠道、渠道亲和与重试路径中，都通过权威槽位租约安全地进入、等待和退出；Redis 异常不会导致跨实例超卖，无限制渠道不产生 Redis 开销，取消、超时或结果不确定的获取也不会留下无法回收的槽位或等待计数。

**Blocked by:** None (can start immediately).

**Status:** implemented

- [x] 缺失的槽位与等待设置采用已确认默认值：并发满时等待开启、等待超时 `5000 ms`、单渠道最大等待数 `0`、槽位 TTL `30 min`、等待基础间隔 `100 ms`。
- [x] 槽位与等待数值遵守已确认边界：等待超时为最大 `60000 ms` 的正整数，单渠道最大等待数 `0` 表示自动跟随渠道并发上限且显式值最大 `10000`，槽位 TTL 为最大 `1440 min` 的正整数，等待基础间隔为最大 `5000 ms` 的正整数；非法值不会成为运行时配置。
- [x] 每个受限渠道请求都经过权威且原子的槽位判定；过期租约被回收，同一请求可以续租而不重复占槽，并发争抢与多实例运行均不会突破渠道并发上限。
- [x] Redis 作为权威状态源时，槽位获取错误保持失败关闭，不降级为可能跨实例超卖的本地放行。
- [x] 渠道并发上限小于或等于零的渠道保持无限制语义，其负载读取与槽位获取均不访问 Redis。
- [x] 等待队列的容量检查、登记和过期设置原子完成；等待关闭时满载请求不登记，等待开启时并发突发不会越过等待上限，释放槽位后等待请求可以继续获取。
- [x] 等待请求超时或取消后，其等待计数最终归零；正常完成、上游失败、请求取消与超时后，其槽位租约最终释放。
- [x] 等待重试从配置的基础间隔开始，在当前间隔的 `[1/2, 1)` 区间抖动并指数增长，封顶为 `max(基础间隔, min(基础间隔 × 8, 1 s))`，且始终受总等待超时约束。
- [x] 结果不确定的槽位获取至多触发一次与请求取消解耦且不超过 `500 ms` 的尽力清理，不重试清理；未清理租约最终由槽位 TTL 回收。
- [x] 外部行为测试覆盖普通渠道选择、指定渠道、渠道亲和和重试换绑，证明成功与所有失败退出路径都会释放对应租约，并验证等待成功、等待超时、等待取消、权威 Redis 故障及无限制渠道零 Redis 行为。
