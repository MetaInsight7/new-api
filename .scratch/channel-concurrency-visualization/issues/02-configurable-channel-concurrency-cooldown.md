# 02: 可配置的渠道并发冷却

**What to build:** 平台根据可热更新的全局渠道并发冷却策略处理 relay 上游反馈：明确的 HTTP 429 默认使渠道进入短期冷却，模糊限流消息默认不触发冷却，额度、配额和余额类错误始终排除；冷却中的渠道暂时不参与后续选择，并在冷却到期后自动恢复。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 渠道并发冷却策略包含总开关、冷却时长、HTTP 429 触发开关和模糊错误消息触发开关；缺失设置采用总开关开启、冷却时长 `30 s`、HTTP 429 开关开启、模糊消息开关关闭的默认值。
- [ ] 冷却时长只接受 `1–3600 s` 的整数；无效值不会成为运行时策略，也不会造成读写双方观察到不同的有效边界。
- [ ] 冷却总开关具有最高优先级；关闭后，HTTP 429 或模糊消息均不会使渠道进入并发冷却。
- [ ] 在不属于额度、配额或余额错误的前提下，总开关与 HTTP 429 开关均开启时，上游 HTTP 429 使对应渠道进入并发冷却；关闭 HTTP 429 开关后，同一响应不触发并发冷却。
- [ ] 模糊消息开关开启时，已定义的限流、过载或容量不足语义可触发并发冷却；该开关关闭时，相同消息不触发并发冷却。
- [ ] 额度不足、配额耗尽和余额不足及其中英文等价语义的排除优先于 HTTP 状态和模糊消息两条触发路径；这类错误即使返回 HTTP 429 或命中通用限流词也不会进入并发冷却。
- [ ] 渠道进入并发冷却后暂时不参与后续候选选择，但不会被持久化为禁用；冷却时长届满后无需人工操作即可重新参与选择。
- [ ] 受限渠道的权威槽位获取在同一个原子判定中检查当前并发冷却、清理过期租约、检查渠道并发上限并登记或续租槽位；冷却在负载观察与实际抢槽之间发生时，请求仍不能越过冷却状态获取槽位。
- [ ] 任一冷却设置变更后无需重启即可作用于后续 relay 请求；并发读取与更新受到同步保护，每次决策读取一份内部一致的策略快照，竞态检查不报告数据竞争。
- [ ] 外部行为测试贯穿真实 relay 请求与后续渠道选择，覆盖默认值、总开关、HTTP 429 开关、模糊消息开关、额度／配额／余额排除、冷却到期恢复以及观察后抢槽前进入冷却的竞态，并证明上游反馈会按当时生效的一致策略改变后续选择。
