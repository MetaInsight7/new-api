# 08: 渠道负载监控聚合接口

**What to build:** 为拥有 `ChannelRead` 权限的管理员提供只读渠道负载监控聚合接口，只针对设置了并发限制的渠道，在同一次有界快照中完成名称／ID、状态、类型、分组和负载筛选，返回服务端分页明细与不受分页影响的全量瞬时汇总；接口复用现有负载缓存、singleflight、Redis 分批和抓取保护，不建立第二套状态来源或修改槽位所有权。

**Blocked by:** 03 和 05

**Status:** implemented

- [x] `GET /api/channel/concurrency/monitor` 要求 `ChannelRead` 并声明等价 PAT scope；未认证、权限不足和 scope 不匹配请求均被拒绝。
- [x] 接口支持页码、页大小、名称／ID搜索、启用状态、渠道类型、分组、负载状态及排序参数；不支持 Key 搜索或标签汇总行。
- [x] 负载状态支持全部、满载、有排队和冷却中，静态筛选先于负载筛选，汇总与分页使用同一个最终受限渠道集合。
- [x] 返回当前页脱敏受限渠道及其并发快照、总数、页码、页大小、快照时间、受限渠道实际使用的类型与分组选项，以及受限渠道 RPM、活跃槽位、总槽位、等待请求和冷却渠道汇总。
- [x] RPM 通过一次最近 60 秒消费日志的 `GROUP BY channel_id` 聚合计算，未命中日志时返回 `0`，不逐渠道请求或查询；普通渠道日志不进入汇总。
- [x] 默认按优先级降序、ID 升序，支持 ID、优先级、槽位占用率和等待数排序；分页变化不会改变相同筛选条件下的汇总数字。
- [x] 只查询和展示受限渠道并调用现有有界负载读取；普通渠道不进入明细、RPM、类型或分组选项，且保持零 Redis 读取。
- [x] 大候选集继续按每批最多 50 个渠道读取，并复用缓存、singleflight、最多 2 个共享抓取槽位和 3 秒边界，不逐渠道往返 Redis。
- [x] HTTP 与服务测试覆盖权限、scope、筛选、排序、分页、全量汇总、无限制、超限、空结果、错误和读取预算。
