# 11: 渠道负载监控集成验收

**What to build:** 在聚合接口、独立监控页面和紧凑编辑分别完成后进行跨切片验收，证明权限、全量汇总、服务端分页、Redis 有界读取、桌面与移动展示、自动刷新、陈旧数据和上限编辑能够协同工作，并留下不调用真实上游、可恢复的验证记录。

**Blocked by:** 08、09 和 10

**Status:** implemented

- [x] 后端定向与相关回归证明聚合接口授权正确、汇总不受分页影响、负载筛选与排序正确且不改变槽位所有权。
- [x] 聚合与页面验收证明普通渠道不进入监控明细、RPM、类型或分组选项；四个筛选按钮直接复用渠道页分面筛选组件。
- [x] Redis／内存测试证明聚合读取继续遵守缓存、singleflight、50 渠道分批、共享抓取和超时边界。
- [x] 前端定向测试、七语静态键、TypeScript、受影响 lint／格式与生产构建通过。
- [x] 桌面浏览器验收覆盖导航、四张汇总卡片、URL 筛选、分页、手动与自动刷新、陈旧状态、只读和可写弹层。
- [x] 移动浏览器验收覆盖汇总、筛选、10 条分页、负载卡片和权限允许的编辑，不依赖横向表格。
- [x] 动态状态使用受控数据或本地 Redis，不调用真实上游；修改渠道并发上限前记录原值，并在成功或失败退出时恢复。
- [x] `verification.md` 追加本轮实际执行命令、结果、环境前提和任何既有非本功能失败，不以旧票据结果冒充本轮验证。
