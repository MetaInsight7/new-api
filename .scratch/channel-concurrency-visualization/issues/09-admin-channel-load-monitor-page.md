# 09: 管理侧渠道负载监控页面

**What to build:** 在管理侧导航“渠道”之后增加“渠道负载监控”，让拥有 `ChannelRead` 的管理员通过四张纯数字汇总卡片、URL 可恢复筛选、服务端分页桌面表格和移动负载卡片观察瞬时渠道负载；页面每 10 秒可见时刷新，失败保留最后成功快照并明确陈旧状态，不增加图表、历史或最近测试响应。

**Blocked by:** 08

**Status:** implemented

- [x] 路由要求管理员角色和 `ChannelRead`，侧边栏只增加一个独立入口且渠道列表页不增加第二入口。
- [x] 顶部显示受限渠道 RPM、活跃／总槽位及文字百分比、排队请求和冷却渠道四张数字卡片，不渲染圆形图或其他图表。
- [x] 名称／ID、启用状态、类型、分组和四种负载筛选写入 URL；类型与分组菜单只列受限渠道实际使用的值，筛选或排序变化重置到第一页。
- [x] 桌面默认每页 20 条并显示渠道、类型、分组、优先级／权重、槽位占用、排队和状态；渠道列收窄，类型、分组、优先级和渠道状态直接复用渠道页组件，不显示最近响应或独立操作列。
- [x] 页面只显示设置了并发限制的渠道，槽位占用同时显示原型式进度条和紧凑 `active/max`，按空闲／运行中／满载或超限着色；普通渠道不进入列表或汇总。
- [x] 移动端默认每页 10 条并使用负载卡片，复用相同的类型、分组、只读优先级、渠道状态、负载状态和槽位进度组件，不依赖横向表格。
- [x] 页面挂载立即请求，可见时每 10 秒轮询，隐藏时暂停、恢复时立即刷新，并提供手动刷新。
- [x] 首次失败显示错误和重试；后续失败保留最后成功数据并显示陈旧标记、最后更新时间，不产生重复轮询 toast。
- [x] Root 可跳转现有全局并发策略，非 Root 不显示入口；所有管理员写操作继续由 `ChannelWrite` 控制。
- [x] 七种语言、路由权限、导航、汇总、筛选、分页、共享渠道组件、槽位进度、桌面、移动、刷新和错误语义均有定向组件测试。
