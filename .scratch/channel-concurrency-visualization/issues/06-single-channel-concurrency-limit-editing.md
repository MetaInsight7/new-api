# 06: 单渠道并发上限编辑

**What to build:** 拥有 `ChannelWrite` 权限的管理员可从渠道列表行内控件或渠道编辑抽屉一致地修改单条真实渠道的渠道并发上限；正整数设置限制，显式 `0` 持久化清除限制，其他部分更新不会误改该值，成功后列表快照范围与状态及时匹配新配置，失败时保留原配置和可重试体验。只读管理员、标签汇总行和批量操作不获得编辑入口。

**Blocked by:** 05

**Status:** implemented

- [x] 只有拥有 `ChannelWrite` 权限的管理员能在桌面渠道列表的真实单渠道行看到并操作行内渠道并发上限控件；只有 `ChannelRead` 权限的管理员仍可查看 Ticket 05 的状态但看不到可执行编辑控件。
- [x] 行内控件只接受非负整数；正整数提交后持久化为该渠道的新渠道并发上限，并使后续请求受到新上限约束。
- [x] 行内控件明确提交 `0` 时会把 `0` 持久化并清除渠道并发限制，不会因零值更新语义而保留旧上限。
- [x] 更新渠道时未提供渠道并发上限，或明确提供 `null`，均保持原渠道并发上限不变；编辑其他渠道字段不会意外设置或清除该值。
- [x] 新增渠道和更新渠道均拒绝负数渠道并发上限，返回可理解的请求错误并保持既有数据不变；前端在发送前阻止负数与非整数输入。
- [x] 渠道编辑抽屉与行内控件采用相同的非负整数、正数设置和 `0` 清除语义，不会因入口不同产生不同持久化结果。
- [x] 编辑成功后，受限渠道之间的正整数变更会刷新其并发快照；无限制渠道改为正数时会进入当前快照查询集合并获取状态，受限渠道改为 `0` 时会退出集合并恢复无限制展示，不沿用旧快照。
- [x] 编辑请求失败时不把未持久化值冒充为已保存配置，不切换快照查询集合或清除最后成功状态，并保留明确反馈与再次编辑、重试的能力。
- [x] 标签汇总行始终显示不可编辑语义，不出现行内控件；本切片只支持单渠道编辑，不增加选择、多选、批量设置或批量清零入口。
- [x] `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi` 均覆盖行内编辑、非负整数校验、`0` 清除、保存成功与失败反馈，没有缺失键或意外回退。
- [x] 定向 HTTP 测试覆盖 `ChannelWrite` 授权与拒绝、正整数设置、显式 `0` 持久化、字段缺失与 `null` 保持、负数新增与更新拒绝，并证明失败请求不会改变数据库中的原值；清零更新表达式同时验证 SQLite、MySQL 与 PostgreSQL 兼容性，不依赖单一数据库的 GORM 零值行为。
- [x] 定向组件测试覆盖只读无控件、可写行内编辑、正整数与 `0` 提交、非法输入阻止、抽屉一致性、成功后的快照刷新与查询集合切换、失败保留、标签不可编辑、无批量入口以及七语静态键完整性。
