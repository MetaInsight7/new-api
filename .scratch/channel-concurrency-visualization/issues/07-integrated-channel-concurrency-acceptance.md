# 07: 渠道并发功能集成验收

**What to build:** 在各功能票据独立完成后，对完整渠道并发能力进行跨切片收口，证明后端运行时、管理界面和权限边界能够在桌面端与移动端协同工作，并留下可复核、可恢复且不产生真实上游费用的验收证据。

**Blocked by:** 04 和 06

**Status:** implemented

- [x] 相关后端与前端全量回归通过，且各功能票据已分别依据自身验收标准独立完成；本票不作为其他票据完成的前置条件，仅在这些票据完成后收口。
- [x] 竞态检查覆盖本功能涉及的并发运行与策略热更新范围并通过，没有新增数据竞争。
- [x] 七种受支持语言的静态键检查、前端类型检查、功能范围 lint／格式检查和生产构建通过；全仓 lint／格式与 i18n sync-diff 的固定基线既有失败已复现并记录，不计为本功能回归。
- [x] 桌面端与移动端 Playwright 验收贯穿只读、可写和 Root 权限，覆盖并发状态展示、单渠道并发上限编辑与清零、移动端约定，以及全部 12 项渠道并发策略的查看、保存和刷新持久化。
- [x] 动态并发、等待和冷却场景使用受控测试状态或浏览器网络夹具完成，不调用真实上游模型，也不产生供应商费用。
- [x] 浏览器验收在修改前记录渠道并发上限和 12 项全局设置的原值，并以 `try/finally` 等价保障在成功或失败退出时恢复全部临时值。
- [x] `verification.md` 记录本次实际执行的命令、环境前提、退出结果和必要证据，不以计划命令、推测结果或其他票据的旧记录冒充本次验证。
