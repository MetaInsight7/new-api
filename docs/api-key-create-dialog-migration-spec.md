# API Key 创建弹窗适配规格

## Problem Statement

当前 Base 的 API Key 创建和编辑界面使用右侧抽屉，Available Models 页面中的分组操作只能跳转到 API Key 列表，不能把用户当前查看的分组带入创建流程。Overlay 已将 API Key 表单改为居中 Dialog，并提供了从模型分组深链接创建、分组预选、模型范围预览和 URL 参数消费能力。

本次迁移必须保留 Base 已有的 API Key 表单字段、服务端校验、Auto 分组、跨分组重试、模型限制、IP 限制和安全行为，不能因为复制 Overlay 界面而引入 Overlay 的 PLG、fixed-account 或供应商专属逻辑。

## Solution

将 Base 的 API Key 创建/编辑表单适配为 Overlay 的 Dialog 交互，并接入 Available Models 的分组创建闭环：用户从某个分组发起创建时，打开 API Key Dialog，自动选择该分组，并在表单旁展示该分组实际可用的模型；关闭 Dialog 后清理深链接参数，刷新页面不会重复打开。

## User Stories

1. 作为普通用户，我希望在 Available Models 页面点击分组的创建按钮后直接打开 API Key 创建 Dialog，以便不需要再次寻找创建入口。
2. 作为普通用户，我希望从分组发起创建时自动预选当前分组，以便新 API Key 与我正在查看的模型范围一致。
3. 作为普通用户，我希望可以从 API Key 页面直接打开创建 Dialog，以便保留现有创建入口。
4. 作为普通用户，我希望创建 Dialog 展示当前分组实际可用的模型，以便在保存前确认 API Key 的模型范围。
5. 作为普通用户，我希望模型预览显示供应商、协议、价格、可用性状态和专属倍率，以便理解该分组下的调用范围和计费提示。
6. 作为普通用户，我希望模型预览在模型访问接口加载中显示稳定的加载状态，以便知道 Dialog 仍在准备数据。
7. 作为普通用户，我希望模型访问接口失败时看到可重试的错误状态，而不是无法解释的空表单。
8. 作为普通用户，我希望在窄屏设备上仍能完成 API Key 创建，并通过独立的模型预览入口查看模型范围。
9. 作为普通用户，我希望在宽屏设备上同时看到表单和模型预览，以便减少来回切换。
10. 作为普通用户，我希望手动修改分组后模型预览同步变化，以便预览始终反映当前表单选择。
11. 作为普通用户，我希望提交表单时仍使用 Base 现有的字段校验和错误提示，以便非法输入不会绕过校验。
12. 作为普通用户，我希望创建成功后仍按 Base 现有流程展示新 API Key 并刷新列表。
13. 作为普通用户，我希望编辑已有 API Key 时保留已有分组和限制，不被创建深链接的默认分组覆盖。
14. 作为普通用户，我希望传入不存在或不可见的分组时回退到 Base 的默认可用分组，而不是创建一个无效 API Key。
15. 作为普通用户，我希望关闭创建 Dialog 后 URL 中的创建参数被清理，以便浏览器刷新不会再次打开 Dialog。
16. 作为普通用户，我希望重复进入同一个创建深链接时只打开一次 Dialog，不因 React 渲染或数据刷新重复重置表单。
17. 作为管理员，我希望 API Key 编辑仍使用相同的 Dialog 外壳，但不受到创建分组深链接的影响。
18. 作为系统维护者，我希望该迁移继续使用 Base 的用户分组、可见分组和 Auto 分组语义，以便后续维护不需要同时维护两套权限模型。

## Implementation Decisions

- API Key 创建和编辑共用 Dialog 外壳；仅改变 Overlay 与 Base 之间的布局和打开方式，不复制 Overlay 的品牌、PLG、fixed-account 或供应商业务逻辑。
- 深链接使用 `open=create` 表示打开创建 Dialog，使用可选 `group` 表示请求的分组；原有 API Key 页面搜索参数继续保留。
- 路由层负责解析和清理深链接参数，Dialog 关闭时使用 replace 导航清除 `open` 和 `group`，不污染浏览器历史。
- 分组解析使用已有的用户模型访问聚合结果和 Base 的分组解析函数。请求分组必须经过可见性校验；无效分组回退到 Base 的创建默认分组规则。
- 创建模式在模型访问数据准备完成后初始化分组；用户已经手动修改分组后，后续数据刷新不得覆盖用户选择。编辑模式始终优先使用已有 API Key 数据。
- 模型预览复用 Available Models 的 `ModelAccessPreview`，不新增重复的模型、价格、供应商或倍率接口。预览使用当前选择分组的可用模型和倍率上下文。
- 宽屏 Dialog 采用表单与模型预览并排布局；窄屏保留表单主流程，并通过独立的预览入口查看模型范围。Dialog 内容和表单区域使用现有滚动与可访问性封装。
- 现有 Base API Key 字段和行为必须保留，包括名称、额度、有效期、无限额度、分组、Auto 分组顺序、跨分组重试、模型 allowlist、IP 白名单和服务端错误处理。
- 创建成功、编辑成功、API Key 展示和列表刷新沿用 Base 现有流程；不改变 API 请求 payload 和后端权限校验契约。
- 预览为空、模型访问加载失败、模型访问有旧数据但刷新失败均使用明确的空状态或重试状态，不把失败静默转换为空模型列表。

## Testing Decisions

- 路由测试验证创建深链接的解析、无效参数清理、关闭后的 replace 清理以及原有列表搜索参数保留。
- 创建状态测试验证：首次深链接只打开一次、模型访问数据加载后预选分组、无效分组回退、用户手动修改后不被刷新覆盖、编辑模式不受创建参数影响。
- API Key Dialog 组件测试从用户行为出发验证：创建/编辑标题、分组预选、模型预览加载和失败重试、提交按钮状态、关闭行为和成功刷新。
- Available Models 组件测试验证分组创建链接携带正确的 `open=create` 和 `group` 参数。
- 模型预览复用现有 Available Models 测试，专属倍率使用显式 `hasOwn` 语义验证，包括倍率为 `0` 的情况。
- 受影响前端文件运行 Oxlint、TypeScript 类型检查和相关 Vitest；涉及路由和 Dialog 的关键流程使用 Playwright 验证宽屏和窄屏行为。
- 不测试 Dialog 内部私有 state 或完整 Tailwind class 快照，优先断言用户可见状态、可访问名称、URL 和对外提交结果。

## Out of Scope

- 不迁移 Overlay 的 PLG 独立分组、fixed-account 独立账户、定价分组/充值分组拆分。
- 不改变 Base 的 API Key 后端接口、数据库结构、权限校验或计费逻辑。
- 不新增 `/v1/available_models` 或其他重复模型接口。
- 不迁移 Overlay 的整套侧栏、品牌营销页面或供应商业务。
- 不在本次实现模型专属倍率的可视化配置编辑器；该配置能力已有 JSON 编辑入口，另作为独立体验改进评估。

## Further Notes

- Overlay 的组件文件名仍可能保留 `drawer` 历史名称，但其实际容器已经是 Dialog；本次以实际组件行为而不是文件名作为迁移依据。
- Base 当前 Available Models 页面已有模型浏览、价格、状态和分组展示能力，本次只补齐从分组到 API Key 创建的闭环，不重复实现页面主体。
