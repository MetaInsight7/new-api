# ADR 0007：敏感词风控采用持久计数、分离解封与限期证据

## 状态

Accepted

## 决策

以 PR #7565 的规则、审计和后台能力为基础，敏感词违规次数采用从上次明确清零起永久累计的口径，自动封禁使用默认关闭的独立开关和单一全局阈值；启用自动封禁时不特殊处理已有计数。普通用户和非 Root 管理员命中阻断规则时按请求累计一次违规，并在自动封禁开启且达到阈值时禁用账号。Root 命中时同样被阻断、形成审计并累计次数，但不会触发自动封禁。只有显式加入敏感词白名单的用户命中后放行并形成审计，且不累计次数、不自动封禁。

达到阈值时只禁用用户、标记该状态由敏感词自动封禁产生，并使现有认证状态失效，不修改余额、订阅或 API Key 的持久状态。敏感词解封与普通账号启用分离：专用解封只接受当前确由敏感词自动封禁的禁用账号，成功后启用用户、清除来源标记并清零违规次数，因此原有有效 Key 随账号恢复；管理员通过普通用户管理显式启用或禁用账号时会接管账号状态并清除来源标记，普通启用仍不清零。清零次数、解封和白名单保持为独立操作，并受独立的敏感词风控管理权限控制；这些操作不要求填写原因，也不新增专门的操作明细审计，继续保留系统已有的基础管理日志。

敏感词检查只作用于请求输入，不检查或改写模型输出。`block` 和 `observe` 规则对每个独立会话只匹配最新输入轮次中的 user 文本和工具结果；普通 Prompt 视为单独一轮 user 输入，Gemini 批量请求则分别选择每个独立子请求的最新输入轮次。Claude `tool_result`、Gemini `FunctionResponse` 和 Responses `function_call_output` 等文本型工具结果与触发它们的 user 输入归属同一轮；请求没有新 user 文本、只有工具结果时仍检查这些结果及同轮 user 文本。纯图片、音频或空白的 user 消息仍推进最新输入轮次，避免重新扫描历史文本，但内部轮次边界不参与扫描和证据留存。历史轮次以及 system、developer、assistant、工具定义、工具调用参数和响应 Schema 不参与匹配；原样重试违规输入时，该输入仍位于最新输入轮次，因此仍会被处理。协议提取出的历史和非输入字段只在最新输入轮次命中后作为审计上下文候选，结构字段、ID 和非模型上下文 metadata 始终不参与匹配。系统不主动下载或解析 PDF/TXT 等附件，不执行图片 OCR 或音频转写，也不扫描 Base64 与文件二进制。视频生成、通用异步任务、Midjourney、Suno、通用任务插件自定义字段和 OpenAI Realtime WebSocket 事件均不纳入本次范围；Responses WebSocket 的 `response.create` 仍属于受支持的 Responses 请求。扫描不设置独立于全局请求体限制之外的文本大小上限；最新输入轮次中的每个可检查字段使用同一 automaton 扫描，`observe` 命中继续收集，首个适用的 `block` 命中被保留后立即停止扫描剩余文本。命中按“规则 ID + 词条”去重并最多保留 256 个；同一次请求只形成一条审计、写一条使用日志并最多累计一次违规。实现不能拼接大文本、收集同一规则词条的重复位置或为每个词再次遍历全文。

新规则写入时，去除首尾空白并按大小写去重后，单个词条最多 200 个 Unicode 字符，单条规则最多 10,000 个词条。一次性迁移旧词表时先导入并启用全部合规词条；超长或超过单规则上限的词条跳过并写入运维告警，旧 Option 或兼容列保持原值以供人工恢复。单个坏词不会阻止迁移标记提交，也不会使已导入的合规保护失效；迁移标记提交后运行时只读取新表。

检查发生在认证和协议解析成功之后、渠道选择和额度预扣之前；因此一个可解析的请求即使随后会因模型不可用、没有渠道或额度不足而失败，命中阻断规则时仍会阻断、审计并计数。无法解析的请求不进入敏感词判断，由协议校验返回原始错误。

对外错误按可恢复性区分：普通阻断返回不可重试的 HTTP `400 invalid_request_error / sensitive_words_detected`；本次命中触发自动封禁以及之后的请求均返回不可重试的 HTTP `403 permission_error / user_banned`。Claude 路径使用 Claude 错误外壳并附带请求 ID；Gemini 原生路径使用 `{error:{code,message,status}}`，其中 `400` 映射为 `INVALID_ARGUMENT`、`403` 映射为 `PERMISSION_DENIED`。敏感词错误不返回 `Retry-After`，也不暴露命中词、规则、证据、累计次数或准确封禁阈值；这些信息仅供管理员审计。系统默认拦截文案只提示请求被记录以及重复违规可能停用账号，并按用户或请求语言返回简中、繁中或英文；已有管理员自定义文案不被迁移覆盖并按配置原样返回。

审计证据采用结构化上下文：保存 system/developer、命中项和命中轮次此前三轮对话；一轮由一次 user 输入及其后续 assistant/tool 链组成，Tool 不单独占一轮。真正命中的字段优先保留，每个选中字段最多保存一次。单个文本字段不超过配置上限时保留原文；超过上限时，优先围绕该字段首个 `block` 命中截取一个窗口，没有 `block` 时围绕首个 `observe` 命中截取，其他命中继续通过位置和短片段保留。非命中上下文字段继续从开头截断。该上限只约束审计证据，不限制请求扫描范围；证据按序列化后的总字节数另行限制为 512 KiB，不保存图片、音频、文件二进制或 Base64 载荷。完整证据及命中词、规则、Prompt 哈希和审计 ID 等敏感元数据使用独立的敏感词审计读取权限，不能由风控管理权限或普通日志权限隐式获得；非 Root 管理员即使拥有该权限，也不能读取 Root 的审计证据。

证据留存语义与 PR #7565 对齐：默认保留 180 天，到期清空完整上下文、脱敏预览和命中片段，但保留审计事实。清理任务的分批、重试和多节点互斥可以改进，但不得改变上述留存结果。

## 后果

- 永久计数简单且可解释，但零散历史命中仍可能在未来达到阈值；管理员可通过独立清零操作处理误判。
- 人工解封会恢复原有 Key；若判断 Key 已泄露，管理员需要在 Key 管理中另行禁用或删除。
- 审计证据与审计事实具有不同生命周期，后台与权限检查必须始终区分两者。
- 只检查最新输入轮次可以避免历史污染并降低长对话的扫描成本；最新工具结果不会绕过检查，但可信 API 调用者仍可把文本放入历史、system/developer/assistant 或工具定义与参数来绕过该层检查，跨轮拆分的词条也不会合并匹配。
- 超大的最新输入轮次仍产生与文本长度成正比的扫描成本；系统依赖全局请求体限制、请求限流与用户并发限制控制最坏输入规模。
