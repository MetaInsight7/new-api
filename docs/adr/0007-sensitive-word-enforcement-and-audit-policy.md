# ADR 0007：敏感词风控采用持久计数、分离解封与限期证据

## 状态

Accepted

## 决策

以 PR #7565 的规则、审计和后台能力为基础，敏感词违规次数采用从上次明确清零起永久累计的口径，自动封禁使用默认关闭的独立开关和单一全局阈值；启用自动封禁时不特殊处理已有计数。普通用户和非 Root 管理员命中阻断规则时按请求累计一次违规，并在自动封禁开启且达到阈值时禁用账号。Root 命中时同样被阻断、形成审计并累计次数，但不会触发自动封禁。只有显式加入敏感词白名单的用户命中后放行并形成审计，且不累计次数、不自动封禁。

达到阈值时只禁用用户并使现有认证状态失效，不修改余额、订阅或 API Key 的持久状态。敏感词解封与普通账号启用分离：专用解封会启用用户并清零违规次数，因此原有有效 Key 随账号恢复；普通启用不清零。清零次数、解封和白名单保持为独立操作，并受独立的敏感词风控管理权限控制；这些操作不要求填写原因，也不新增专门的操作明细审计，继续保留系统已有的基础管理日志。

敏感词检查只作用于请求输入，不检查或改写模型输出。首期检查覆盖已接入协议中本次请求的模型可见结构化文本，不按 user、assistant、system、developer 或 tool 角色缩小范围；结构字段、ID 和非模型上下文 metadata 不参与匹配。Tool 参数和返回中的普通文本参与检查，但系统不主动下载或解析 PDF/TXT 等附件，不执行图片 OCR 或音频转写，也不扫描 Base64 与文件二进制。现有通用 Relay 协议之外只补充视频生成和通用异步任务的标准 `prompt` 字段；Midjourney、Suno、通用任务插件的任意自定义字段和 Realtime WebSocket 事件不纳入本次范围。扫描不设置独立于全局请求体限制之外的文本大小上限，实现必须按字段单次扫描、只保留有界的唯一命中与片段，不能拼接大文本、收集每次重复命中或为每个词再次遍历全文。

检查发生在认证和协议解析成功之后、渠道选择和额度预扣之前；因此一个可解析的请求即使随后会因模型不可用、没有渠道或额度不足而失败，命中阻断规则时仍会阻断、审计并计数。无法解析的请求不进入敏感词判断，由协议校验返回原始错误。

审计证据采用结构化上下文：保存 system/developer、当前项和此前三轮对话；一轮由一次 user 输入及其后续 assistant/tool 链组成，Tool 不单独占一轮。真正命中的字段优先保留，证据按序列化后的总字节数限制为 512 KiB，不保存图片、音频、文件二进制或 Base64 载荷。完整证据及命中词、规则、Prompt 哈希和审计 ID 等敏感元数据使用独立的敏感词审计读取权限，不能由风控管理权限或普通日志权限隐式获得；非 Root 管理员即使拥有该权限，也不能读取 Root 的审计证据。

证据留存语义与 PR #7565 对齐：默认保留 180 天，到期清空完整上下文、脱敏预览和命中片段，但保留审计事实。清理任务的分批、重试和多节点互斥可以改进，但不得改变上述留存结果。

## 后果

- 永久计数简单且可解释，但零散历史命中仍可能在未来达到阈值；管理员可通过独立清零操作处理误判。
- 人工解封会恢复原有 Key；若判断 Key 已泄露，管理员需要在 Key 管理中另行禁用或删除。
- 审计证据与审计事实具有不同生命周期，后台与权限检查必须始终区分两者。
- 超大结构化文本仍产生与文本长度成正比的扫描成本；系统依赖全局请求体限制、请求限流与用户并发限制控制最坏输入规模。
