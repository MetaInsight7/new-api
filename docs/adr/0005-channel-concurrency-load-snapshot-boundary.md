# ADR 0005：渠道并发负载快照仅作为观察提示

## 状态

Accepted

## 背景

渠道选择需要比较受限渠道的活跃请求数、等待请求数和冷却状态，管理侧也需要读取这些瞬时状态。若每次路由与管理轮询都为全部候选渠道读取实时状态，读取成本会随候选集规模增长；大量相同候选集同时参与选择或观察时，还会形成重复查询并放大共享状态存储的压力。

这些负载数据在被读取后就可能立即变化，因此即使不使用缓存，它们也只是选择时刻的观察结果，而不是可供后续请求消费的容量承诺。短时复用负载快照可以降低重复读取成本，但不能改变并发上限的正确性边界。

## 决策

负载快照缓存只用于观察渠道负载。快照可以排列候选渠道的尝试顺序、作为短期冷却状态的排序或过滤提示，也可以供管理侧展示瞬时状态，但不得代表、预留、转移或释放并发槽位。

每个受并发限制的请求在选定候选渠道后，仍必须执行权威的槽位获取操作。该操作是请求获准使用渠道的唯一判定点，必须依据当时的真实状态原子地检查冷却状态与并发上限，并在成功时登记该请求自己的槽位租约。快照显示尚有容量、缓存被关闭或调用方持有此前读取的结果，都不能绕过这一步；权威获取失败时，应继续尝试其他候选渠道或进入既定等待流程。

缓存允许在一个有界的短时间窗口内陈旧。陈旧快照可能让系统先尝试一个刚刚满载的渠道、暂时低估或高估候选负载，或者稍晚发现刚刚结束的冷却。可接受的后果仅限于候选顺序短暂次优、增加一次权威获取尝试或延迟使用刚恢复的渠道；它不得导致超过渠道并发上限，也不得制造一个未经权威获取确认的槽位租约。

## 后果

- 路由与管理侧可以复用相同候选集的短时快照，并合并并发读取，从而降低状态读取压力。
- 渠道分配在缓存窗口内可能不是瞬时最优，但并发上限仍由权威槽位获取保证。
- 缓存键必须包含会改变负载含义的候选身份与并发上限；返回给调用方的快照不能共享可变所有权状态。
- 缓存失效、绕过或读取失败只能影响排序质量和读取成本，不能切换到基于快照直接放行的模式。

## 考虑过的方案

- 缓存槽位所有权或把快照中的剩余容量当作可消费配额：拒绝。并发请求、多个应用实例、进程故障和缓存过期都会使本地视图分叉，造成超卖、长期少卖或无法可靠释放槽位。
- 在读取快照后不再执行权威槽位获取：拒绝。读取与实际使用之间存在竞争窗口，即使每次都读取最新状态，也无法把观察结果变成原子容量承诺。
- 完全禁用缓存并为每个请求实时读取全部候选渠道：拒绝。该方案正确但会让共享状态存储的工作量随候选集规模和请求量相乘，并在缓存同时失效或流量突增时产生重复读取。
- 通过截断候选集来限制读取成本：拒绝。它会隐藏较低优先级但仍可用的回退渠道，改变现有路由与降级语义；应通过短时缓存、并发读取合并和分批读取控制成本，而不是丢弃候选渠道。
